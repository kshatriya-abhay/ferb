# How Ferb works

The details behind the [README](../README.md): how a request becomes tool calls, when Ferb asks first, each tool, how Ferb understands you (voice, rewrite, tool selection), Ferb Link, and routing. For building, testing and tuning, see [development.md](development.md).

## What it does in detail

- **A chat:** your requests on the right, the assistant's replies on the left, newest at the bottom; scroll up for the history. A request shows at once, with a "Thinking…" bubble until Needle 3 answers.
- **Requests to tool calls:** each request goes to Needle 3 with the tools it mentions (see *Routing*), as JSON schemas, and Needle 3 returns the calls it needs, with a confidence. The app checks every argument itself, then:
  - runs the calls straight away when the confidence clears the bar for the tools called;
  - asks first ("Do it" / "Skip") below that;
  - says so when no tool fits.
- **A default bar per tool**, set from the desktop check (adjustable per tool): just above the confidence of the tool's wrong calls, while letting most right ones run. Opening an app, the alarm list, the agenda and calendar events 0.3, alarms, timers and notes 0.4, volume 0.5, settings pages and directions 0.6, media and camera 0.7, flashlight 0.75 (talk about the torch, "my flashlight is broken", reads as "turn it on" at up to 0.70). Cactus's general advice is 0.7 for everything; Needle 3's confidence varies a lot with phrasing (the same alarm request scores 0.3–0.9), so a single 0.7 bar asked about most good requests.
- **Buttons on results:** "Turn off" / "Turn on" for the flashlight, a slider on the volume result (drag to change the media volume), the opposite media action, "Show alarms" and "Show timers" (to change or delete them in the clock app), "Open again" for apps and pages.
- **Keywords per tool** pick the tools a request goes to; a call to a tool the request doesn't mention (possible with the fallback) asks first, whatever its confidence. They match whole words, also with an "s" on the end ("alarm" finds "alarms"), and each tool's can be changed in its settings.
- **Numbers must come from the request:** an alarm time or timer length with a number the request doesn't say asks first ("I hate alarms" became an alarm at 6:45, the tool's example, at 0.63). Number words count ("half past six").
- **Calls that open another app run one at a time**, each after the assistant is back in front: two alarm intents 14 ms apart set only the first on HyperOS.
- **Every tool is configurable:** Settings → Tools lists them; each row's switch turns the tool on or off, and the rest of the row opens its page:
  - on or off;
  - **always confirm before running** (on by default for Calls and Messages, which reach other people, and Calendar, where a day or time read wrong is easy to miss; turning it off warns that it's not recommended);
  - Android permissions it needs, e.g. the contacts for Calls and Messages, calls for Calls, and the calendar for Agenda and Calendar: asked for when the tool is turned on, and from the reply (**Allow**) when a request needs one Ferb doesn't have. Without them a tool does what it can: Calls opens the dialer, Messages the messages app with the message written, Agenda and Calendar the calendar app;
  - a **confidence slider** (0.10–1.00, steps of 0.05) from which it runs without asking, with a reset to its default;
  - its **keywords**, on a page of their own: add, edit (tap a word), delete, or reset to the tool's own words. Saved only when changed, so later changes to the defaults reach everyone else;
  - the tool's own options, e.g. **which clock** alarms and timers go to (the phone's clock app for now; more providers later), or **which calendar** new events go to (your Google account's own until you pick one);
  - examples, and the schema Needle 3 gets.
  
  Changes across the Tools list and the tools' pages are one draft with one **Save**; leaving with unsaved changes asks. Nothing needs reloading after a save: each request picks its tools from the saved set.
- **The phone's assistant:** Ferb can be picked as the digital assistant app, because an activity of its own (`AssistActivity`) takes `ACTION_ASSIST`. That's one of the two things Android's assistant role accepts; the other, a `VoiceInteractionService`, isn't needed yet. The assist gesture (holding the power button, or the corner swipe) then opens an M3 Expressive bottom sheet over the app in front, half the screen high, which starts listening at once (with audio processing off, or the microphone refused, its box takes focus with the keyboard up). It shows what's heard as it comes, then the reply and any "Shall I do this?", with ✕ and ✓ as in the chat. Tapping the conversation or its open button, or dragging the sheet up, opens the full chat, which carries the same conversation (the chat's state is the app's, `AssistantApp.chat`); a request still on its way finishes there. Swiping down, a tap outside, or back (with predictive back) closes it, dropping a recording. The sheet is in its own task, out of Recents, so it closes back to that app. Its screen-context extras aren't read, and no permission is added.
- **Tools** (all offline, none needs the assistant role):

A note whose words aren't mostly the request's asks first |

| Show lists (`show_list`) | | The list's unticked items in the chat, each with a box that ticks it in the file (one character) |

Reminders are kept only in Ferb's own store (`reminders.json`): a title, a time and a repeat, never on a note (since 2026-10-23; before, a reminder could live in a note's frontmatter as `remind:`/`repeat:`, and those were read into the store once on the first start after, without writing to the notes, whose keys stay as harmless leftovers). A destination whose words aren't mostly the request's asks first |

Tapping it calls them at once (`ACTION_CALL`, with `CALL_PHONE`; without it, the dialer with the number). A typed number is offered the same way. ## How Ferb understands you

Needle 3, on the phone, always makes the tool call. Before it, up to three steps help it understand a request (`pipeline/`, `AnswerFlow`). **Settings → Choose your preferred model** (`ModelChoice`) picks them in one go: **Needle + Whistle** (audio Whistle, no rewrite), **Gemini Nano** (audio and rewrite by Gemini Nano; Whistle and no rewrite until each part is ready, then it switches) or **Gemma 4 (via Ferb Link)** (audio and rewrite by Ferb Link; a step that fails falls back for that request). Tool selection is off in all three: Jev is only under Advanced. Typing works with each. Gemini Nano is greyed out where AICore can't run it, Gemma 4 until Ferb Link is installed; installed but not paired, Gemma 4 can be picked and says so, with a button to open Ferb Link. With nothing chosen, Gemini Nano where it can run, else Needle + Whistle. Changing a step under Advanced unselects the model; saved steps that are exactly a model's became it, once (`Pipeline.toModel`). **Settings → Advanced** sets them one by one:

| Step | Options | Default |
|---|---|---|
| **Audio processing**: what turns your voice into text | Off (no mic) · Whistle (on the phone, English) · Gemini Nano (on the phone, English and Hindi) · Ferb Link (Gemma 4 on your computer) | Gemini Nano if AICore says it's available, else Whistle |
| **Prompt rewrite**: "Helps with other languages and improves accuracy." | Off · Gemini Nano · Ferb Link (Gemma 4) | Gemini Nano if its model is available, else Off |
| **Tool selection**: "Improves accuracy by narrowing the tool choice." | Off · Ferb Link (Jev) | Off |

Ferb Link's options are greyed out, with why, until Ferb Link is installed and paired (and, for audio, while the computer's model takes no audio; for Jev, while Jev is off in Ferb Link). The defaults apply to steps not chosen yet, once AICore has answered; until then, Whistle and no rewrite. The settings from before the steps were carried over once (2026-10-24): "Voice on this phone" off became audio off, Gemini Nano picked to hear stayed Gemini Nano, Computer picked in the chat became Ferb Link for audio and the rewrite, and "Use Jev to select the tool" became Jev.

**The rewrite** turns every request, typed or heard, English, Hinglish or Hindi, into one short plain English command, or NONE when nothing is asked of the phone (a question, a how-to, chat, a statement, something it can't do): NONE answers "Nothing for me to do on the phone there." without Needle 3. Gemini Nano (the ML Kit Prompt API, through AICore) and Gemma 4 (through Ferb Link's `rewrite` with Ferb's own prompt as `instructions`) get the same prompt, `GeminiRewrite.PROMPT` (v2), greedy, at most 40 tokens, and Ferb reads both answers by the same rules. On the phone bench (text only, 2026-10-24): Needle 3 alone 360 of 461 right, after the v2 rewrite 405 (none of 137 expected-none: 75 against 122); on 78 held-out lines written for it, 61 against 70; Hindi and Hinglish 6 against 22 of 24. The rewrite costs about 0.3 s (median, Gemini Nano FULL). A typed request the rewrite changed shows "Understood as …" under it; a spoken one, "Heard: …".

**Tool selection** sends the request (as rewritten) and the routed tools' names and descriptions to Jev, TypeSafe's cloud model, through Ferb Link, which holds its key and a spending limit; Ferb itself stays offline. From a probability of 0.5 (`LinkPolicy.JEV_BAR`), Needle 3 gets only Jev's tool and runs it at that tool's own bar with the usual checks; "none" means no call.

**On the first launch** (and from Settings → Run setup again), after the welcome, the model page offers the same three choices, with the recommended one picked (Gemini Nano where it can run, else Needle + Whistle) and why one can't be used here; with Gemini Nano picked, it's set up on the page itself: the check, a download button, a moving bar while it downloads (no amount: AICore's model is shared across apps, so its byte counts may mislead; they're only logged), a failed download's reason with Try again, or one line when AICore can't run it. When it's done is AICore's checkStatus, not the download's callbacks (`ReadyWatch`): with Ferb in front it asks every 10 s, backing off to 30 s while nothing changes and at least 500 ms between checks, and at once when the download says it finished; it stops when ready, failed or after half an hour (then Try again). Each time Ferb comes back to the front it checks once. When ready, the page says "Gemini Nano is ready" and the chat shows a one-line note. There's no notification while Ferb is away: nothing shows AICore allows checkStatus from the background (it blocks some background use), so Ferb waits for the next resume. Gemini Nano can be picked while it's still to download (tapping it starts the download; Next only saves it): Ferb uses Whistle meanwhile and switches as each part is ready, as the app follows Gemini Nano's state from the first check on (`AssistantApp.followGemini`). Next saves the option shown, so a default can't change later under the user; Skip keeps what's chosen and goes to the chat. The tools page says you can choose which tools Ferb can use, and that some need a permission first; its button opens Settings → Tools (and each tool's page) over the setup, and Back returns to the tools page (`Onboarding`, which holds the page while it's away; a tool's page there has no Try it, which would end setup before the assistant page). Every tool that needs no setup (no permission, special access, folder or other app) is on by default; Calls, Messages, Agenda, Calendar, Reminders and the three list tools start off until set up. So setup has no chat tip about tools any more; Settings → Tools keeps its one-time tip. A last page opens the phone's assistant setting to make Ferb the assistant (`openAssistantSettings`: voice input settings, which on Android 17 is the Digital assistant app page itself; else Default apps with the assistant row highlighted; else Settings); back in Ferb it says once Ferb is the assistant. It's left out when Ferb already is (`OnboardingFlow`, `Page`).

**When a step fails** for a request, that request goes on without it, and the reply says so ("Rewrite · Gemini Nano instead"; the details say why at length): Ferb Link's audio falls back to Whistle on the same recording, Ferb Link's rewrite to Gemini Nano when it's set up (else the words as they are), a failed Gemini Nano rewrite to the words as they are, and Jev to none. An older Ferb Link that ignores Ferb's prompt counts as a failed rewrite.

**The path in the details:** tapping a reply shows the steps the request took, as they ran, with each step's pick or confidence: "Voice: Gemini Nano → Rewrite: Gemini Nano → Tool selection: Jev (Alarms, 0.93) → Needle 3 (0.81)", or "Typed → Rewrite: off (Ferb Link: not set up) → Needle 3 (0.81)".

**Voice:** with audio processing on, the chat box shows the mic beside Send. Tap the mic and speak: Gemini Nano's words show as they're heard. It sends by itself once you've spoken and then been quiet for 2 s (a ring round ✓ fills meanwhile); with no speech in 8 s it stops and sends nothing ("Didn't hear anything"). **✓** stops and sends at once; **✕** cancels, and nothing is sent. A recording stops at 30 s and waits for Send. Speech is found on the recording's own PCM (Whistle, Ferb Link: 20 ms frames' energy against a noise floor from the first 300 ms, with hysteresis, and 300 ms of it before it counts, so a click or a cough doesn't), or from Gemini Nano's partial results, a new one counting as speech (`Endpoint`, `EnergyVad`). An empty transcript is never sent.
- **Gemini Nano** (ML Kit GenAI Speech Recognition, Advanced mode, on Pixel 10 and 11): it listens on the microphone itself, in AICore. It hears Hindi too when set to English (it writes it in Devanagari); its language is on its page (Settings → Gemini Nano), with each part's setup and whether it's downloading. When it can't hear here (not set up, or unavailable), Whistle hears that request.
- **Whistle:** Ferb records 16 kHz mono float PCM and Whistle, Cactus's speech model bundled beside Needle 3 on the same engine, transcribes it in English. A clip whose loudness doesn't rise and fall like speech (20 ms frames, 90th against 10th percentile, under 12 dB) never reaches it, and an empty transcript is "No words heard". While Whistle runs, the screen keeps still: the engine pins its workers to cores. It loads on the first spoken request and stays loaded.
- **Ferb Link (Gemma 4):** the same PCM, sent as AAC (`AacEncoder`, about 4 KB a second, under Ferb Link's 512 KB). The computer returns what it heard (Hindi in Latin letters) and an English command; with the rewrite on, what it heard goes on to the rewrite, with it off, its command does. Ferb asks Ferb Link to wake the computer's model when recording starts, and, at most once a minute, when the chat box is tapped while a step uses the computer.

**Privacy:** the mic only records while the box shows a recording. Gemini Nano runs in AICore on the phone; Ferb has no INTERNET permission (ML Kit's network permissions are removed from its manifest, so its usage logs can't be sent). Only the steps set to Ferb Link send anything to your computer, over Tailscale, and only tool selection to TypeSafe.

## Ferb Link: a bigger model on your computer

**Ferb Link** (in its own repo) is a companion app that holds the internet access Ferb doesn't have and passes a step's request to a model on your own computer, such as a laptop on your Tailscale network running Gemma 4 E2B through llama.cpp, or to Jev. Ferb talks to it through one `ContentResolver.call` on its content provider (`link/FerbLink.kt`, Ferb's copy of Ferb Link's `LinkContract`, version 1), so Ferb itself stays offline; Ferb Link answers only apps signed with its key. Ferb uses its `status`, `check`, `wake`, `transcribe` (audio processing), `rewrite` (with `instructions`: Ferb's prompt) and `decide` (Jev). Gemma's own tool calls (`complete`, Computer mode until 2026-10-24) are no longer used: Needle 3 always makes the call.

**Settings → Ferb Link** shows whether the computer answers, and, until Ferb Link works, a checklist that ticks itself off from Ferb Link's status and Ferb's own check: install it (from Releases), set up its server (its quick start), Tailscale on both, pair (the computer's QR code, `ferblink://pair`), switch it on, the computer answers. Choosing Gemma 4 (via Ferb Link) uses it for audio and the rewrite; Advanced sets which steps use it, one by one. Ferb also suggests Ferb Link once in the chat, after Needle 3 has found no tool or been unsure three times while Ferb Link isn't set up; dismissed, it doesn't come back.

## Routing

Needle 3 weighs every tool when it has five or fewer; with more, only the five that best match a request, so a right tool can be left out. So the app doesn't give it every tool turned on: each request gets only the tools whose keywords it contains (`ToolRouter`), and `needle_init` re-runs on the loaded model when that set changes (about 0.1 s on the phone; the model isn't reloaded). A request that mentions no tool gets every tool turned on, as before routing, and Needle 3's own pick of the five that match best ("I want to watch youtube" → YouTube); those calls ask first, since the request doesn't name the tool. The details sheet shows which tools were checked.

On the desktop check with all nine tools, routing kept as many answers right as giving Needle 3 every tool (111 vs 110 of 132), and raised the confidence of right calls (opening apps: 0.38–0.95 → 0.64–0.96). The confident wrong calls left are harmless: "I hate alarms" shows the alarm list, "what apps do I have" opens the apps settings page.

A setting to check every tool, five at a time, when the mentioned ones gave no call was removed on 2026-10-12: on the desktop check it added one right call that runs and let unrelated requests reach tools, and Ferb Link now answers when Needle 3 finds nothing. `tool-check`'s `fallback` mode still measures it.

## Notes in Ferb

With a notes folder picked, the chat's top bar has **Notes**, a screen with two primary tabs (tap or swipe between them). **Notes** lists the notes Ferb made there, newest first: those with its `ferb-id` in their frontmatter (the notes and lists it created). The folder's other notes aren't listed, though the tools still find them by name, so a list kept by hand still takes "add milk to the shopping list".

**Reminders** has two sections, each with its header only when it has rows. **Upcoming** lists every reminder still to come, soonest first: its title, its next time ("Today 9:00 pm", "Tomorrow 7:00 am", "Tue 28 Oct, 6:30 pm"; a snoozed one by its snooze) and its repeat ("Daily", "Every Monday", "Monthly", "Yearly"). It's the same list the alarms are set from (`ReminderBook.upcoming`), so the two can't drift; it's read again when the screen comes back and whenever a reminder is added, fires, or changes. Rows aren't clickable. Each has a clear button ("Clear reminder"): no confirmation; the reminder goes from Ferb's store (a repeat entirely, not just its next time), its alarm is cancelled and a notification of it taken down. A snackbar, "Reminder cleared", offers Undo, which brings it back with its time, repeat and snooze, and its alarm. Editing comes later. **Recent** lists the reminders whose last occurrence showed or was marked Done in the past 24 hours, newest first, in quieter rows (secondary text colour, a muted tick): "Done 9:00 am", "Was due 9:00 am", "Was due yesterday 9:00 pm". A repeat can be in both: Upcoming at its next time, Recent for the occurrence that just showed. Each reminder keeps when its last occurrence showed (`firedAt`) and when Done was tapped (`doneAt`); Done no longer removes a one-off, which stays a day and is then pruned (on launch, after a reboot or update, and as reminders fire). Recent's clear button takes the entry off: a one-off goes, a repeat stays scheduled; Undo puts it back. With neither section: "No upcoming reminders. Ask Ferb to remind you."

On the Reminders tab only, a **New reminder** extended FAB (it scales and fades in with the tab, and shrinks to its icon once the list scrolls) opens a New reminder page: M3's full-screen dialog pattern for a short form on a phone, with Close and Save in the top bar. Title, Date (M3 date picker, from today), Time (M3 time picker; both start at the next whole hour) and Repeat (Doesn't repeat, Daily, Weekly on that weekday, Monthly, Yearly). Save is on once there's a title and the time is still to come. It saves through `ReminderBook.add` with no note, as `add_reminder` does, then schedules the alarms; without notifications allowed it asks first, as the tool does (exact alarms come with `USE_EXACT_ALARM`; without them the alarm is inexact, as for the tool). Then it's back to the Reminders tab, scrolled to the new row. Close or Back drops what was typed, without asking.

A reminder's reply in the chat (`add_reminder`, or a reminder from `set_alarm` on another day) has **Reminders** next to **Undo**: it opens the Notes screen on the Reminders tab, as any screen opens.

**Opening a note:** tapping one (in the list, or **Open** in the chat) opens it in Obsidian; Ferb has no viewer or editor of its own. Obsidian on Android opens notes only through `obsidian://open` links (no VIEW for `.md` files or `content://` URIs), so Ferb builds one from the note's document (`ObsidianLink`): `vault=` the picked folder's name (Obsidian names a vault after its folder, so pick the vault itself) and `file=` the note's path from it without `.md`. `path=` (an absolute path) opens Obsidian but not the note on Android. It's a plain VIEW, and opens the note whether Obsidian is already open or not. A `<queries>` entry for the `obsidian` scheme lets Ferb see Obsidian; it's not a permission. When a folder is picked, Ferb checks that it's a vault's top folder by looking up a `.obsidian` entry by that exact name (never listing the folder; only on the phone's storage and SD cards, whose document ids are paths). Without one, Settings and the Notes screen warn, without blocking: "This folder doesn't look like an Obsidian vault. Pick the vault's top folder so notes open in Obsidian." A subfolder would give the wrong vault and path, and its grant can't see its parents. Links reach a vault Obsidian has opened at least once (forum reports say links to a never-opened vault fail silently on mobile), which the option's note says. Without Obsidian (uninstalled after picking Markdown notes), tapping a note says "Install Obsidian to open this note"; saving, lists and reminders keep working through the Storage Access Framework.

## Inside the app

```
text box ─► AssistantViewModel ─► AssistantEngine ─► Needle.kt ─JNI─► assistant_jni.cpp ─► libneedle.a
            checks and runs calls    tools, facts      one engine thread   maps the bundled    (prebuilt)
                                                                           model from the APK
```

- The model is stored uncompressed in the APK and read through `AAssetManager`, so it's mapped in place rather than copied.
- The engine is process-global, not thread-safe and has no unload call; every call runs on one thread, and the model stays loaded while the app runs.
- System facts (date, locale, device) are given with the tools; the app re-initialises when the date changes.

## Navigation

Moving between Ferb's screens follows Material 3's motion: forward is the shared X axis (the new screen slides in 30 dp from the end as the old one slides away, both fading), welcome to chat is a fade through ([transition patterns](https://m3.material.io/styles/motion/transitions/transition-patterns)), with the theme's Expressive springs ([motion specs](https://m3.material.io/styles/motion/overview/specs)). Back, by button or gesture, pops the screen; the predictive back gesture shrinks the screen to 90% over the one beneath as it's dragged, and a cancelled swipe settles back ([predictive back](https://developer.android.com/design/ui/mobile/guides/patterns/predictive-back)). On the chat, back is the system's back-to-home animation (`enableOnBackInvokedCallback`). Ferb keeps its own screen stack (`NavStack`: a seekable transition driven by `PredictiveBackHandler`), so no navigation library. With unsaved tool changes, back on Tools asks first instead.
