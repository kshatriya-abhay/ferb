# How Ferb works

The details behind the [README](../README.md): how a request becomes tool calls, when Ferb asks first, each tool, Ferb Link and voice, and routing. For building, testing and tuning, see [development.md](development.md).

## What it does in detail

- **A chat:** your requests on the right, the assistant's replies on the left, newest at the bottom; scroll up for the history. A request shows at once, with a "Thinking…" bubble until Needle 3 answers.
- **Requests to tool calls:** each request goes to Needle 3 with the tools it mentions (see *Routing*), as JSON schemas, and Needle 3 returns the calls it needs, with a confidence. The app checks every argument itself, then:
  - runs the calls straight away when the confidence clears the bar for the tools called;
  - asks first ("Do it" / "Skip") below that;
  - says so when no tool fits.
- **A default bar per tool**, set from the desktop check (adjustable per tool): just above the confidence of the tool's wrong calls, while letting most right ones run. Opening an app, the alarm list, the agenda and calendar events 0.3, alarms, timers and notes 0.4, volume 0.5, settings pages and directions 0.6, media and camera 0.7, flashlight 0.75 (talk about the torch, "my flashlight is broken", reads as "turn it on" at up to 0.70). Cactus's general advice is 0.7 for everything; Needle 3's confidence varies a lot with phrasing (the same alarm request scores 0.3–0.9), so a single 0.7 bar asked about most good requests.
- **Buttons on results:** "Turn off" / "Turn on" for the flashlight, a slider on the volume result (drag to change the media volume), the opposite media action, "Show alarms" and "Show timers" (to change or delete them in the clock app), "Open again" for apps and pages.
- **Keywords per tool** pick the tools a request goes to; a call to a tool the request doesn't mention (possible with the fallback) asks first, whatever its confidence. They match whole words, also with an "s" on the end ("alarm" finds "alarms"), and each tool's can be changed in its settings.
- **Numbers must come from the request:** an alarm time or timer length with a number the request doesn't say asks first ("I hate alarms" became an alarm at 6:45, the tool's example, at 0.63). Number words count ("half past six").
- **Calls that open another app run one at a time**, each after the assistant is back in front: two alarm intents 14 ms apart set only the first on HyperOS.
- **Every tool is configurable:** Settings → Tools lists them; each row's switch turns the tool on or off, and the rest of the row opens its page:
  - on or off;
  - **always confirm before running** (on by default for Calls and Messages, which reach other people, and Calendar, where a day or time read wrong is easy to miss; turning it off warns that it's not recommended);
  - Android permissions it needs, e.g. the contacts for Calls and Messages, calls for Calls, and the calendar for Agenda and Calendar: asked for when the tool is turned on, and from the reply (**Allow**) when a request needs one Ferb doesn't have. Without them a tool does what it can: Calls opens the dialer, Messages the messages app with the message written, Agenda and Calendar the calendar app;
  - a **confidence slider** (0.10–1.00, steps of 0.05) from which it runs without asking, with a reset to its default;
  - its **keywords**, on a page of their own: add, edit (tap a word), delete, or reset to the tool's own words. Saved only when changed, so later changes to the defaults reach everyone else;
  - the tool's own options, e.g. **which clock** alarms and timers go to (the phone's clock app for now; more providers later), or **which calendar** new events go to (your Google account's own until you pick one);
  - examples, and the schema Needle 3 gets.
  
  Changes across the Tools list and the tools' pages are one draft with one **Save**; leaving with unsaved changes asks. Nothing needs reloading after a save: each request picks its tools from the saved set.
- **The phone's assistant:** Ferb can be picked as the digital assistant app, because its main activity takes `ACTION_ASSIST`. That's one of the two things Android's assistant role accepts; the other, a `VoiceInteractionService`, isn't needed yet. The assist gesture then opens the chat with the box focused. Its screen-context extras aren't read, and no permission is added.
- **Tools** (all offline, none needs the assistant role):

| Tool | On by default | How |
|---|---|---|
| Alarms (`set_alarm`) | ✓ | `AlarmClock.ACTION_SET_ALARM`, skipping the clock app's UI; the next time it's that time of day |
| Timers (`set_timer`) | ✓ | `AlarmClock.ACTION_SET_TIMER` |
| Open apps (`open_app`) | ✓ | Launch intent; the name is matched against the launcher's apps by the app, not the model |
| Settings pages (`open_settings`) | ✓ | `Settings.ACTION_*` (Wi-Fi, Bluetooth, battery, display…, or Settings itself) |
| Flashlight (`set_flashlight`) | ✓ | `CameraManager.setTorchMode` |
| Show alarms (`show_alarms`) | | `AlarmClock.ACTION_SHOW_ALARMS` |
| Media volume (`set_volume`) | | `AudioManager.setStreamVolume` on the media stream; requests about the ringer, alarm or notification volume ask first. The reply's slider follows the volume changed outside Ferb (volume keys, another app, the system panel) while it's on screen, through the VOLUME_CHANGED broadcast (no permission), but not while it's being dragged |
| Media controls (`control_media`) | | Media key events |
| Camera (`open_camera`) | | `MediaStore.INTENT_ACTION_STILL_IMAGE_CAMERA` |
| Notes (`create_note`) | | Google's "create note" action (`com.google.android.gms.actions.CREATE_NOTE`, the one its "Take a note" voice command sends) with the note as `EXTRA_TEXT`; Google Keep and other notes apps take it (Keep opens it in a small dialog to save, it doesn't save it by itself), and with several Android asks which. A note whose words aren't mostly the request's asks first |
| Lists (`add_to_list`) | | Lists are notes in the notes folder (Settings → Tools → Notes, picked through the Storage Access Framework, e.g. in an Obsidian vault) with Markdown tasks, `- [ ] milk`. Finds the list by name (as said, or by sound), else makes a new note with Ferb's id in its frontmatter; appends `- [ ] item` lines in the file's own line endings; Undo removes them while they're still the last lines. Ferb never rewrites a file whole: Syncthing syncs it |
| Show lists (`show_list`) | | The list's unticked items in the chat, each with a box that ticks it in the file (one character) |
| Tick off (`check_off`) | | Ticks the first unticked item that matches (as said, or by sound), on the list named or the one that has it; Undo unticks |
| Reminders (`add_reminder`) | | Kept by Ferb and shown as its own notification at the exact time (`USE_EXACT_ALARM`), with Done and Snooze (10 minutes). A repeat moves to its next time as its notification shows, Done tapped or not. After a reboot or an update they're rescheduled: a repeat missed meanwhile moves on, and a one-off missed shows late ("Due 9:00 am"), once. The app reads the time from the request ("in 20 minutes", "tomorrow at 9", "Friday" meaning 09:00) and the repeat from its words ("every Monday"). A reminder on a note writes `ferb-id`, `remind: 2026-10-20 09:00` and `repeat` in the note's frontmatter, so it survives a rename and is rebuilt from the folder, and a `remind:` added in Obsidian becomes a reminder too (the folder is read on launch, at each reminder, after a reboot and daily). Needs notifications allowed; Undo removes it |
| Directions (`get_directions`) | | Google Maps' directions link (`https://www.google.com/maps/dir/?api=1&destination=…`), which Maps opens as a route to check and start; Maps looks the place up, so the app stays offline. The app reads the travel mode from the request's words (walking, cycling, scooter or bike, bus or train, driving), not from Needle 3, which filled one in for every request. A destination whose words aren't mostly the request's asks first |
| Calls (`make_call`) | | Finds the person in the contacts (`READ_CONTACTS`, read on the phone only) by spelling, by sound ("Shriyans" finds "Shreyansh") and by relation ("mum" finds "Maa"; Devanagari names are transliterated), and offers the best match, with "Open dialer" to find someone else. Tapping it calls them at once (`ACTION_CALL`, with `CALL_PHONE`; without it, the dialer with the number). A typed number is offered the same way. Without asking (if you turn that off), it only opens the dialer with the best match (`ACTION_DIAL`), so nobody is rung without being picked. Always asks first by default |
| Messages (`send_text`) | | Finds the best-matching contact the same way and shows them with the draft, to Proceed or Cancel. Proceed opens the messages app with the message written (`ACTION_SENDTO` with `sms_body`, no SMS permission): you press send. Always asks first by default |
| Agenda (`show_agenda`) | | Lists a day's events in the chat, read from Android's calendar provider (`READ_CALENDAR`; Google Calendar syncs it, so the app stays offline), with repeating events, all-day ones on their own dates, and only the calendars your calendar app shows. Tap an event to open it, or "Open calendar" for the day. The app reads the day from the request ("tomorrow", "Friday", "12 Oct"), not from Needle 3, which doesn't know today's date; a day that isn't one ("the agenda of the G20 summit") asks first |
| Calendar (`add_event`) | | Shows the event (title, day and time, the calendar, any clash with what's already there) and adds it on "Add" (`WRITE_CALENDAR`, straight into the calendar provider), with "Open" and "Undo" on the result. The app reads the day and time from the request: "tomorrow at 5", "Saturday from 2 to 3:30 pm", "next Tuesday morning", "for 2 hours"; a day alone is all day, a time alone the next time it comes, and an event lasts an hour unless an end or length is said. Without the permission, it opens the calendar app's new-event screen filled in (`ACTION_INSERT`), to save there. Always asks first by default |

## Ferb Link: a bigger model on your computer

**Ferb Link** (work in progress, in its own repo) is a companion app that holds the internet access Ferb doesn't have and passes requests to a model on your own computer, such as a laptop on your Tailscale network running Gemma 4 E2B through llama.cpp. Ferb talks to it through one `ContentResolver.call` on its content provider (`link/FerbLink.kt`, Ferb's copy of Ferb Link's `LinkContract`, version 1), so Ferb itself stays offline; Ferb Link answers only apps signed with its key.

**Settings → Ferb Link**, off by default:
- **Off:** Needle 3 answers everything.
- **Choose in the chat:** under the chat box, Phone (Needle 3) or Computer (Ferb Link), kept until changed.

A third mode, "When Needle 3 is unsure" (Needle 3 first, the computer when it was below its bar or found no tool), was removed on 2026-10-23; a saved one became "Choose in the chat" with Phone picked.

With Computer picked, the computer gets the tools Needle 3 would get, one request at a time, with 10 s to answer, and Needle 3 runs only when the computer can't answer (the reply says why). The computer's answers run without asking when the usual checks pass (the tool isn't set to always ask, the request mentions it, and its values are the request's), with no confidence bar: no stand-in for their confidence was safe in the bench (Gemma 4 E2B's first-token probability let 20 wrong calls through even at 1.00), and calls, messages and new events ask by default anyway. Answers from the computer say so with a laptop icon and its time, and Needle 3's answers in its place with a phone icon and why, in a few words (Ferb Link sends a short error and a longer one); tapping a reply opens its details: the model and the reason at length. Until Ferb Link works, Settings → Ferb Link has a checklist that ticks itself off from Ferb Link's status and Ferb's own check: install it (from Releases), set up its server (its quick start), Tailscale on both, pair (the computer's QR code, `ferblink://pair`), switch it on, the computer answers. Ferb also suggests Ferb Link once in the chat, after Needle 3 has found no tool or been unsure three times while Ferb Link is off; dismissed, it doesn't come back.

**Voice with Jev, in Computer mode:** a spoken request's English text (the computer's transcription, already a plain command) goes to Jev, then to Needle 3 with Jev's tool, checked against that text: no second call to the computer. On the audio bench's real speech (2026-10-16) it got 58 of 67 right with 36 run without asking, against Gemma with Jev's tools' 57 and 23. If Jev fails, the computer answers as before, and the reply says why. Typed requests in Computer mode stay with Gemma and Jev's tools; a "comprehend" step, where the computer decides whether a request needs rewriting first (typed Hinglish), is being benched.

**The path in the details:** tapping a reply shows the steps the request took, recorded as they ran, with each step's pick or confidence: "Voice → Gemma transcription → Jev (Alarms, 0.93) → Needle 3 (0.81)", "Typed → Jev timed out → Gemma", "Typed → Gemma: timed out → Needle 3 (0.81)" (`AnswerFlow`, `Step`).

**Jev selects the tool** ("Use Jev to select the tool" on Settings → Ferb Link: off by default, in every mode but Off, and only while Jev is on in Ferb Link, which holds TypeSafe's key and a spending limit). With it on, every request (typed, or a spoken one's English text) goes first to Jev, TypeSafe's cloud model, through Ferb Link: the request's text and the routed tools' names and descriptions (or every tool that's on), never values. Ferb itself stays offline. Jev picks a tool or "none" with a probability. From 0.5 (`LinkPolicy.JEV_BAR`):
- a tool: the answering model gets only that tool. Needle 3 runs it at that tool's own bar plus the usual checks; the computer gets Jev's next tools too (0.25 or more, three in all), so a request for two things can get both, and its answer runs under the usual checks. In "When Needle 3 is unsure", Needle 3 with Jev's tool first, then the computer with Jev's tools;
- "none": no tool, with the usual offers to turn one on.

Below 0.5, failed, after 6 s, or at the spending limit, it's as without Jev, and the reply says why in a few words ("Jev wasn't sure"). The chat box's Phone choice reads "Phone + Jev"; with Computer picked, it shows "Using Jev" under the box instead, and the details show Jev's pick ("Jev picked Alarm (0.93)"). In Ferb's bench (2026-10-16, 460 English requests), right answers / wrong runs: Phone 360 / 19 to 426 / 6, Computer 418 / 21 to 434 / 10, and the since removed "When Needle 3 is unsure" 409 / 33 to 434 / 12; the computer on Hindi and Hinglish 20 to 22 of 24 right, no wrong runs either way. **Known limit:** on the phone Jev's one tool means a request for two things gets at most one, and on the computer one of the bench's seven two-thing requests still ran only the second. It replaced Jev as a third answerer in the chat box and Jev as a second opinion when Needle 3 is unsure (both 2026-10-15/16): one switch over every mode is simpler, and the bench showed every mode gains from it.

**Voice:** the chat box always shows the mic (its trailing icon) beside Send, which is enabled once there's text. Tap the mic, speak, tap stop, then Send (✕ drops the recording); recordings stop by themselves at 30 s and wait for Send.
- **On the phone (Phone picked, or Ferb Link off):** Ferb records 16 kHz mono float PCM and Whistle, Cactus's speech model bundled beside Needle 3 on the same engine, transcribes it in English. Hindi and Hinglish voice needs Computer. A clip whose loudness doesn't rise and fall like speech (Ferb Link's check: 20 ms frames, 90th against 10th percentile, under 12 dB) never reaches Whistle, and an empty transcript is "No words heard". The text then takes the usual path: "Voice → Whistle → Needle 3 (0.81)", with Jev in between when the switch is on. While Whistle runs, the screen keeps still (no animated indicator): the engine pins its workers to cores and slows several times over when the UI competes for them. Whistle loads on the first spoken request and stays loaded (the engine holds one text and one speech model, with no unload).
- **Off (Settings → "Voice on this phone (Whistle)", on by default):** wherever Whistle would hear, the mic is hidden (only the box and Send), and Whistle is never loaded; once loaded, it stays. With Computer picked and the computer taking audio, the mic stays, as Gemma transcribes there.
- **On the computer (Computer picked, and its model takes audio):** Ferb records mono 16 kHz Opus and Ferb Link has the computer transcribe it. The computer returns what it heard (Hindi in Latin letters, as Hinglish is typed) and the request as a plain English command, which Ferb answers like a typed one: its keywords, dates and Needle 3 need English. The request's bubble shows the English command with "Heard: …" under it. Ferb asks Ferb Link to wake the computer's model when recording starts, so its load hides behind the speech. It does the same, at most once a minute, when the chat box is tapped or Computer is picked, for typed requests; spoken requests then follow the same rules as typed ones.

## Routing

Needle 3 weighs every tool when it has five or fewer; with more, only the five that best match a request, so a right tool can be left out. So the app doesn't give it every tool turned on: each request gets only the tools whose keywords it contains (`ToolRouter`), and `needle_init` re-runs on the loaded model when that set changes (about 0.1 s on the phone; the model isn't reloaded). A request that mentions no tool gets every tool turned on, as before routing, and Needle 3's own pick of the five that match best ("I want to watch youtube" → YouTube); those calls ask first, since the request doesn't name the tool. The details sheet shows which tools were checked.

On the desktop check with all nine tools, routing kept as many answers right as giving Needle 3 every tool (111 vs 110 of 132), and raised the confidence of right calls (opening apps: 0.38–0.95 → 0.64–0.96). The confident wrong calls left are harmless: "I hate alarms" shows the alarm list, "what apps do I have" opens the apps settings page.

A setting to check every tool, five at a time, when the mentioned ones gave no call was removed on 2026-10-12: on the desktop check it added one right call that runs and let unrelated requests reach tools, and Ferb Link now answers when Needle 3 finds nothing. `tool-check`'s `fallback` mode still measures it.

## Notes in Ferb

With a notes folder picked, the chat's top bar has **Notes**, a screen with two primary tabs (tap or swipe between them). **Notes** lists the notes Ferb made there, newest first: those with its `ferb-id` in their frontmatter (notes and lists it created, and notes it set a reminder on). The folder's other notes aren't listed, though the tools still find them by name, so a list kept by hand still takes "add milk to the shopping list".

**Reminders** lists every reminder still to come, soonest first, with or without a note: its title, its next time ("Today 9:00 pm", "Tomorrow 7:00 am", "Tue 28 Oct, 6:30 pm"; a snoozed one by its snooze) and its repeat ("Daily", "Every Monday", "Monthly", "Yearly"). It's the same list the alarms are set from (`ReminderBook.upcoming`), so the two can't drift; it's read again when the screen comes back and whenever a reminder is added, fires, or changes. Tapping one with a note opens the note in Obsidian; one without isn't clickable. Each row has a clear button ("Clear reminder"): no confirmation; the reminder goes from Ferb's store (a repeat entirely, not just its next time), its alarm is cancelled, a notification of it is taken down, and its note loses `remind` and `repeat` (its `ferb-id` and the note stay). A snackbar, "Reminder cleared", offers Undo, which brings it all back: the reminder with its time, repeat and snooze, its alarm, and its note's text exactly as it was (or, if the note changed meanwhile, the two keys added again). Editing comes later. With none: "No upcoming reminders. Ask Ferb to remind you."

A reminder's reply in the chat (`add_reminder`, or a reminder from `set_alarm` on another day) has **Reminders** next to **Undo**: it opens the Notes screen on the Reminders tab, as any screen opens.

**Opening a note:** tapping one (in the list, **Open** in the chat, or a reminder's notification) opens it in Obsidian; Ferb has no viewer or editor of its own. Obsidian on Android opens notes only through `obsidian://open` links (no VIEW for `.md` files or `content://` URIs), so Ferb builds one from the note's document (`ObsidianLink`): `vault=` the picked folder's name (Obsidian names a vault after its folder, so pick the vault itself) and `file=` the note's path from it without `.md`. `path=` (an absolute path) opens Obsidian but not the note on Android. It's a plain VIEW, and opens the note whether Obsidian is already open or not. A `<queries>` entry for the `obsidian` scheme lets Ferb see Obsidian; it's not a permission. When a folder is picked, Ferb checks that it's a vault's top folder by looking up a `.obsidian` entry by that exact name (never listing the folder; only on the phone's storage and SD cards, whose document ids are paths). Without one, Settings and the Notes screen warn, without blocking: "This folder doesn't look like an Obsidian vault. Pick the vault's top folder so notes open in Obsidian." A subfolder would give the wrong vault and path, and its grant can't see its parents. Links reach a vault Obsidian has opened at least once (forum reports say links to a never-opened vault fail silently on mobile), which the option's note says. Without Obsidian (uninstalled after picking Markdown notes), tapping a note says "Install Obsidian to open this note"; saving, lists and reminders keep working through the Storage Access Framework.

## Inside the app

```
text box ─► AssistantViewModel ─► AssistantEngine ─► Needle.kt ─JNI─► assistant_jni.cpp ─► libneedle.a
            checks and runs calls    tools, facts      one engine thread   maps the bundled    (prebuilt)
                                                                           model from the APK
```

- The model is stored uncompressed in the APK and read through `AAssetManager`, so it's mapped in place rather than copied.
- The engine is process-global, not thread-safe and has no unload call; every call runs on one thread, and the model stays loaded while the app runs.
- System facts (date, locale, device) are given with the tools; the app re-initialises when the date changes.

## Navigation

Moving between Ferb's screens follows Material 3's motion: forward is the shared X axis (the new screen slides in 30 dp from the end as the old one slides away, both fading), welcome to chat is a fade through ([transition patterns](https://m3.material.io/styles/motion/transitions/transition-patterns)), with the theme's Expressive springs ([motion specs](https://m3.material.io/styles/motion/overview/specs)). Back, by button or gesture, pops the screen; the predictive back gesture shrinks the screen to 90% over the one beneath as it's dragged, and a cancelled swipe settles back ([predictive back](https://developer.android.com/design/ui/mobile/guides/patterns/predictive-back)). On the chat, back is the system's back-to-home animation (`enableOnBackInvokedCallback`). Ferb keeps its own screen stack (`NavStack`: a seekable transition driven by `PredictiveBackHandler`), so no navigation library. With unsaved tool changes, back on Tools asks first instead.
